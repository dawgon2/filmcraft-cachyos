# XPS 16 setup and laptop test list (fork Phase XPS)

FORK-PLAN §1a.99. The laptop: Dell XPS 16 (9640), Core Ultra 7 155H with the Intel Arc (Xe-LPG)
iGPU (expected `renderD128`) and an NVIDIA RTX 4050 Laptop GPU, 6 GB (expected `renderD129`).
Linux assumed (CachyOS like the desktop, §1a.99 (iv)). Everything before the laptop was built and
tested with fake adapter / node / power-supply lists and on the desktop (RX 6700 XT + UHD 770);
this file is what the owner sets up and what the first laptop session runs. Results are
**synthetic** until the owner's own clips are used.

## 1. What the owner installs (once)

All from the distribution's repositories; nothing is built from source. On CachyOS / Arch:

| Package | Why |
|---|---|
| `nvidia-open` (or `linux-cachyos-nvidia-open`) + `nvidia-utils` | NVIDIA's driver: Vulkan, NVENC, NVDEC (CUDA's `libnvcuvid`, `libnvidia-encode`) |
| `intel-media-driver` | Intel's iHD VA-API driver (decode incl. HEVC 4:2:2 10-bit, encode) |
| `vulkan-intel`, `vulkan-icd-loader` | Vulkan on the Arc iGPU (Mesa ANV) |
| `libva-utils` | `vainfo` (the probe reads every render node) |
| `vulkan-tools` | `vulkaninfo` |
| `power-profiles-daemon` or `tuned-ppd` (usually already there) | battery / AC is read from `/sys/class/power_supply`; this only matters for the desktop's own power modes |
| `rustup` (stable), `git`, `ffmpeg` (test fixtures only) | building and testing, as on the desktop |

Then:

1. Enable the NVIDIA DRM modeset (`nvidia_drm.modeset=1`; CachyOS sets it by default) and reboot.
2. ssh access like the Dell (a key in `~/.ssh/authorized_keys`, a `Host xps` entry on the
   desktop), so a session can run the probe and tests there.
3. Clone the fork (`hevc-vaapi`) and `../craft-fonts`; copy the test clips (`target/fixtures/`
   is regenerated by the tests; the X-M5-style 6.2K clips from the desktop's fixture folder).
4. Do **not** set `DRI_PRIME`, `__NV_PRIME_RENDER_OFFLOAD` or `MESA_VK_DEVICE_SELECT` globally:
   the tests check FilmCraft's own choice first, then each override.

## 2. The probe

```
tools/fork/xps-probe.sh                      # report in target/xps-probe-<date>.txt
FILMCRAFT_PROBE_TESTS=1 tools/fork/xps-probe.sh   # also the NVENC / VA-API / 4:2:2 probe tests
```

It records the kernel, CPU / RAM, each GPU with its PCI ids, driver and render node, the GPUs'
runtime power state **before and after** the driver queries (so a query that wakes the RTX 4050
from runtime D3 shows up), the power supplies, NVIDIA's driver version and modeset, the
environment overrides, `vainfo` per node, `vulkaninfo --summary`, `nvidia-smi`, and the display
scaling. Read-only, no sudo.

## 3. The laptop test list (in this order)

Each line: what to run, what passes. Log results in FORK-PLAN §7 and fix what fails (with a test).

**GPU choice (XPS a)**
1. `graphics.listDevices` (control channel): both GPUs listed with kinds; `inUse` is the NVIDIA
   one on Auto. Then Settings ▸ Playback ▸ Graphics device = Power saving → restart → `inUse`
   Intel; Performance → NVIDIA; the Intel GPU by name → Intel. Exports render on the same GPU
   (log line "GPU:" / `perf.stats`).
2. `DRI_PRIME=1`, `__NV_PRIME_RENDER_OFFLOAD=1`, `MESA_VK_DEVICE_SELECT=8086:<id>` one at a time
   with Auto: the driver's first GPU is used.
3. Runtime D3: with Power saving and the dGPU asleep (probe: `runtime_status=suspended`), start
   FilmCraft, open Settings ▸ Playback, close; the dGPU should go back to `suspended` within
   ~10 s of idling. If FilmCraft keeps it awake, fix (listing the GPUs off the start path or only
   when Settings opens; `graphics_device::warm`).

**NVENC (XPS b)**
4. Regenerate `crates/platform/src/nvenc/abi_tests.rs` expectations for the P1 / P2 / P3 / P6 /
   P7 preset GUIDs from NVIDIA's MIT-licensed `nvEncodeAPI.h` 12.1 (docs/testing.md); the values
   in `ffi.rs` were written from the published header without it on the desktop.
5. `cargo test -p filmcraft-platform --test nvenc --test nvenc_hevc --test nvenc_hevc_main10
   --test nvenc_export`: green on the RTX 4050.
6. Export H.265 8-bit SDR with Graphics device = Performance: `perf.stats` names NVENC; with
   Power saving: VA-API on Intel. Encoder speed Speed / Balanced / Quality: three different
   speeds (preset P1 / P4 / P7 in the log), the files play.
7. NVENC Main 10 on Linux: today 10-bit / HDR go to VA-API; try `linux_hevc_encoder` with 10-bit
   (remove the 8-bit gate in a branch), and enable it if the files check out.
8. Pull the plug on NVENC mid-export (e.g. `nvidia-smi --gpu-reset` is not allowed without sudo:
   instead kill the process holding the encoder session, or test with a driver error injected in
   a debug build): the export must end with a message naming NVENC, never crash.

**Decode (XPS c)**
9. 4:2:0 H.264 / HEVC: decoded on Intel (log "hardware decoding through in-process VA-API:
   Intel… on renderD128"), NVDEC only with `FILMCRAFT_NVDEC_FIRST=1`.
10. HEVC 4:2:2 10-bit 6.2K (the X-M5 path): decoded on the Arc iGPU; the 4:2:2 badge offers
    hardware; `va_422_handoff` tests green; frames handed to the NVIDIA GPU (DMA-BUF Intel →
    NVIDIA import: if NVIDIA's Vulkan refuses Intel's modifiers, the copy path must work and the
    log say so).
11. `vainfo` caps match what FilmCraft logs as supported (profiles / entry points read from the
    driver, never assumed).

**Laptop limits (XPS d)**
12. `perf.stats` VRAM budget: shared memory → an eighth of RAM, at most 4 GB.
13. Unplug: `filmcraft_engine::power::on_battery` true within 10 s; with Lower playback resolution
    on battery ticked, playback drops one step; plug in → back. A paired Bluetooth mouse / headset
    battery must not count.
14. Export with the lid open on battery and on AC: the desktop does not suspend during the export
    (portal inhibit).
15. HiDPI: the 16" panel at 1.5× and 2× scaling (KDE Wayland): monitors sharp, UI hit targets
    right (`ui.screenshot` at both); fractional scaling on X11 if used.
16. NVIDIA + Wayland: window opens on Auto / Performance; no flicker / black frames when the
    window moves between scaling factors; suspend / resume with FilmCraft open (device-lost
    path, never a crash).

**Benchmarks (with the laptop, §1a.99)**
17. `xm5-play-full` and `xm5-export-4k` on each GPU, on battery and on AC; Auto on battery vs
    Power saving on battery (decides whether Auto should prefer the iGPU on battery: provisional
    choice in `filmcraft_gpu::adapter_pick`).
18. 8.6c zero-copy (Vulkan ↔ CUDA, NVDEC frames kept on the GPU) and 8.6d two-GPU export (NVENC
    lane + VA-API lane) are built then, not before.

**Accept (tag `xps-1`):** plays and exports on the iGPU, the dGPU and Auto, falls back cleanly,
never crashes; build per §1a.9.
